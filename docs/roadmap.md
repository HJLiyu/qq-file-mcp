# 优化与扩展方向

这个项目的重点是让 Agent 按群、发布人和实际查询范围找到资料，再读取文件或准备准确的作业预览。功能增加后仍应保留可核对的来源、范围和回执。

## v0.8.0 本轮改进

- DOCX 离线阅读：复用现有文件引用和续读工具，按正文段落、表格行返回；不需要 Word 或额外模型服务。
- 状态库连接释放：事务提交或回滚后立即关闭连接，避免 Windows 文件持续被占用。
- 提交文件错误提示：文件被占用、读取或暂存失败时返回 `SUBMISSION_IO`；失败的暂存清理，未发送的预览保留供重新准备。

原生 PDF/Word 上传仍是试验功能。本轮没有向真实 QQ 群或原生群作业发送答案。

## 后续优先级与验收目标

| 优先级 | 方向 | 对用户的作用 | 怎样验收 |
|---|---|---|---|
| 1 | 原生文件提交真实验收 | 明确上传与提交到底能否使用 | 用户选定自己的答案和目标作业后，核对原生提交记录、文件字节哈希与界面回执；超时不自动重复提交 |
| 2 | 扫描 PDF / 图片的可选本地 OCR | 让 Agent 读取截图和扫描课件 | 选定样本页，报告 OCR 来源和置信局限，保留原图及页码；公式无法可靠识别时提示人工核对 |
| 3 | 已下载资料的增量全文检索 | 不知道文件名时按正文内容找资料 | 只索引用户指定的本地下载目录，检索返回准确页/块和原文片段；文件修改、删除后更新索引，保持来源记录 |
| 4 | 作业要求证据清单 | 汇总原生要求及老师后续聊天补充 | 每条要求带来源、发送者、时间及查到的范围；矛盾和截止时间变更显式列出，由 Agent 汇总 |
| 5 | 脱敏演示与易用诊断 | 降低首次使用成本，也便于展示作品 | 无 QQ 账号可复现演示资料检索和 DOCX/PDF 阅读；诊断只显示步骤与错误类别，排除账号、Cookie、令牌及真实聊天 |

OCR 和全文索引应作为可选功能，不要求用户提前整理群文件。群目录与聊天附件的实时检索继续按现有方式随问随查；本地索引只能代表已经下载并被索引的资料，不能证明群内不存在其他文件。
